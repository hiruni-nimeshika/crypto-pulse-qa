# BUG-005: Price alert form accepts zero, negative and invalid target prices

- **Reported by:** Hiruni Nimeshika
- **Observed:** 17 November 2026
- **Area:** Input validation (alerts)
- **Severity:** Medium
- **Priority:** Medium
- **Status:** Fixed in code (found in code review), retest needed
- **Environment:** Source review of `src/App.jsx` (earlier version). Reproduce on any build that lacks the fix.

## Steps to reproduce
1. Open the 'Set Price Alert' form
2. Enter an email, choose a coin, enter -50 (or 0) as the target price
3. Submit

## Expected result
The form rejects non-positive prices with a clear message.

## Actual result
The original input was `type="number"` with no minimum, and the original code relied on a comparison that does not handle empty or non-numeric values reliably. Negative values could be sent to the server.

## Evidence
- Code review of the original `setAlert` function and the target price input.

## Root cause
Missing client-side validation (no `min`, weak check).

## Fix
Added `min="0"` and `step="any"` to the input and a check that the parsed value is a finite number greater than 0 before sending.

## Retest
Try -50, 0, an empty value and 'abc' (the browser blocks letters). Each must show a clear message and send no request. Try 50000: it must be accepted.
